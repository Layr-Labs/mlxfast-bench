The transition from mechanical to electronic computation reshaped how societies store and process knowledge. Early machines filled entire rooms and consumed enormous power to perform a handful of arithmetic operations, yet each generation of hardware compounded the gains of the last. Engineers learned to pack more logic into less space, to schedule work so that idle circuitry did useful things, and to hide the cost of moving data behind clever layers of caching. Software followed the same arc: abstractions that once seemed wasteful became the foundation on which larger systems were built. What remained constant through every era was a simple discipline, that a result is only trustworthy when the process that produced it can be measured, repeated, and checked by someone who did not build it.

Measurement itself became a craft. To compare two machines fairly, one had to hold everything else steady: the same inputs, the same starting temperature, the same amount of memory already warmed by previous work. A benchmark that ran hot could flatter a slow design, and a benchmark that ran cold could punish a fast one. Careful engineers built rituals around these runs. They cooled the hardware to a fixed threshold before starting the clock. They discarded the first measurement, which often reflected the cost of loading data rather than the speed of computing on it. They repeated each trial and reported not a single lucky number but a robust average that shrugged off outliers. Above all, they separated the thing being measured from the thing doing the measuring, so that a component could never quietly report a flattering figure about itself.

The same principles apply when the work is no longer arithmetic but inference over a large statistical model. Such a model reads a sequence of tokens and predicts the next one, and then the next, each step depending on the state accumulated by the steps before it. Two phases dominate the cost. In the first, the model digests a prompt all at once, a burst of parallel work that fills its internal memory with context. In the second, it produces new tokens one at a time, a serial march in which each output feeds back as the next input. The first phase rewards raw throughput; the second rewards low latency per step, because there is little parallelism to hide behind. A fair score weighs both, but weighs the serial phase more heavily, because that is where a real user waits.

To keep such a score honest, the harness that measures must not trust the engine that computes. It sends only token identifiers across the boundary and times the round trips on its own clock. It insists that every returned token be fully materialized, so that no engine can answer quickly by promising to finish the work later. It drains any accumulated memory to a known baseline before each timed phase, so that leftover state cannot subsidize the next measurement. It forbids an engine from recognizing that it is being tested and taking a shortcut reserved for that case. And it closes each phase with a barrier that forces all deferred work to complete and be counted, comparing the count the engine reports against the count the harness issued. A mismatch fails the run outright, because a number that cannot be explained is worse than no number at all.

None of this machinery matters unless the answers are also correct. Speed that produces the wrong continuation is not an optimization; it is a regression wearing a disguise. So alongside the timed phases, the harness replays a set of reference cases whose expected outputs were recorded in advance on trusted hardware. Some cases check that the single most likely next token matches, allowing a small tolerance for the tiny numerical differences between one accelerator and another. Other cases let the model run freely for many steps and check that its output stays on the expected path. Only an engine that is both fast and faithful earns a place on the board, and even then its score is meaningful only against a baseline measured on the very same class of hardware, because a percentage improvement compares honestly only to a reference that shared its conditions.

This is the quiet contract behind every credible benchmark: isolate the measured from the measurer, charge every cost to the party that incurred it, cool and quiesce before you start, repeat and average, and verify correctness before you celebrate speed. The discipline is old, older than the machines it now governs, and it will outlast them too.
